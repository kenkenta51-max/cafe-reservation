# LP専用 共通デザインルールブック v1.0

## 目的

本書は、業種・商品・サービス・ターゲットが異なるLPでも、一定以上のデザイン品質とコンバージョン導線を再現するための共通基準である。

案件ごとの見た目を同じにするためのテンプレートではない。案件に応じて表現を変えながら、情報の分かりやすさ、視線誘導、信頼性、行動のしやすさ、実装品質を担保するために使用する。

## 適用範囲

- BtoC／BtoB
- 有形商品／無形サービス
- 店舗・予約型
- 通販・購入型
- 資料請求・問い合わせ型
- 高額商品・相談型
- セミナー・イベント申込み型
- 採用・応募型

## 本書の位置づけ

LP制作では、次の優先順位で判断する。

1. 法令・媒体審査・アクセシビリティ
2. クライアントの正式なブランドガイドライン
3. 要件定義・訴求設計
4. 本書の共通ルール
5. 業種・案件固有のデザイン方針
6. 参考サイトから抽出した表現

参考サイトの見た目をそのまま優先しない。参考サイトからは原則を抽出し、要件と本書に合わせて再設計する。

# PART 1. LPデザインの最上位原則

## 1-1. デザインの目的

LPのデザインは、装飾することではなく、訪問者が次の内容を迷わず理解し、安心して行動できるようにすることである。

1. 自分向けのページか
2. 何を提供しているか
3. どの悩みを解決できるか
4. どのような結果を得られるか
5. なぜこの商品・サービスを選ぶべきか
6. 信頼できる根拠は何か
7. 料金・条件・リスクは何か
8. 次に何をすればよいか

## 1-2. 訴求設計を見た目へ変換する

デザイン開始前に、次の5項目を確定する。

| 項目 | 内容 |
|---|---|
| 最優先ターゲット | 誰に向けたLPか |
| 主訴求 | 最も伝える価値は何か |
| 信頼根拠 | 主訴求を何で証明するか |
| コンバージョン | 最終的に取ってほしい行動 |
| 主要な不安 | 行動を妨げる最大の理由 |

これらが未確定のまま、色・フォント・装飾から決めない。

## 1-3. 情報の重要度を4段階に分ける

| 階層 | 対象 | 主な表現 |
|---|---|---|
| 最重要 | 主訴求、得られる結果、主要CTA | 最大サイズ、強いコントラスト、十分な余白 |
| 重要 | セクション見出し、ベネフィット、実績 | 中〜大サイズ、太字、色・背景の変化 |
| 補足 | 説明文、条件、手順 | 読みやすい本文、段落、図表 |
| 補助 | 注釈、タグ、出典 | 小さめの文字。ただし判読性を下げない |

すべてを強調しない。強調が多いほど、重要な情報が見えなくなる。

## 1-4. 1セクション1メッセージ

各セクションは原則として、1つの質問に答える。

- 誰向けか
- 何が問題か
- なぜ解決できないか
- どう解決するか
- 何が得られるか
- なぜ信頼できるか
- 他と何が違うか
- いくらかかるか
- どう始めるか

1セクション内に複数の目的を詰め込む場合は、見出しやブロックを分ける。

## 1-5. 見た目の一貫性と構図の変化を両立する

同じ役割の要素は、同じ見た目にする。

- CTAの色・形・文言
- 見出し階層
- 角丸
- 枠線
- 影
- アイコン
- 余白単位
- 写真の色調

ただし、全セクションを同じカード3枚・中央見出し・説明文の構図にしない。情報の種類に応じて、文章中心、写真中心、比較、数値、引用、手順、図解などの構図を使い分ける。

# PART 2. 案件ごとのデザイン方針

## 2-1. 制作前に決める項目

| 項目 | 決定内容 |
|---|---|
| 印象 | 信頼、先進、高級、親しみ、清潔、力強さ等から3つ以内 |
| デザインコンセプト | 誰に、どの価値を、どんな表情で伝えるかを1文で定義 |
| Primary | ブランド・世界観の中心色 |
| CTA | 行動専用の強調色 |
| Background | ページ全体の基本背景 |
| Surface | カード・パネル背景 |
| Text | 主要文字・補助文字 |
| Font | 日本語本文、必要時のみ英字・見出し用 |
| Radius | 角丸の基準 |
| Shadow | 使用有無と強さ |
| Photo direction | 被写体、光、色温度、構図、トリミング |
| Icon direction | 線画／塗り、線幅、色、サイズ |
| Motion | 動きの目的、種類、速度 |

## 2-2. 毎回変えてよい要素

- 配色
- フォントの選定
- 写真・イラストの方向性
- 角丸の程度
- 枠線・影の使い方
- セクションごとの構図
- 装飾モチーフ
- アニメーション

ただし、各要素はデザインコンセプトと矛盾させない。

## 2-3. 全案件で変えない品質基準

- 情報の優先順位が見た目で分かる
- 本文が無理なく読める
- CTAが他の要素と明確に区別される
- 余白に規則性がある
- 同じ役割の要素が統一されている
- 画像に明確な役割がある
- スマートフォンで情報順を再設計している
- コントラストと操作性を確保している
- 実績・数値・口コミを捏造しない
- 表示速度を損なう演出を避ける

# PART 3. ファーストビュー

## 3-1. 役割

ファーストビューは、訪問者が「自分に関係がある」「続きを見る価値がある」と判断する領域である。

## 3-2. 必須要素

- 最優先ターゲット
- 商品・サービスの内容
- 得られる結果または主要ベネフィット
- 競合と区別できる要素
- 主要CTA
- 信頼を補強する短い根拠
- 内容を象徴する商品・人物・利用場面のビジュアル

すべてを文章で詰め込まず、主訴求を最優先する。

## 3-3. 広告・検索語との一致

広告、SNS投稿、検索意図、営業資料などの流入元で約束した内容と、ファーストビューの主訴求を一致させる。

- 表現を完全一致させる必要はない
- 誰向けか、課題、得られる結果、オファーは矛盾させない
- 流入元にない別の訴求を最上位に置かない

## 3-4. レイアウト

- PCではテキストとビジュアルの主従を明確にする
- スマートフォンではH1、補足、CTA、信頼根拠、画像の順序を意図的に決める
- 重要情報が画面外へ押し出されるほど大きな装飾を置かない
- 画像上に文字を置く場合は、オーバーレイ等でコントラストを確保する

## 3-5. H1の目安

| 端末 | 基準 |
|---|---|
| PC | 48〜72px |
| スマートフォン | 32〜44px |

文字数・改行・商材の印象に応じて調整する。大きさだけで迫力を作らない。

## 3-6. ファーストビューの禁止事項

- 抽象的なキャッチコピーだけで内容が分からない
- 主要CTAと補助CTAを同じ強さで表示する
- 実績バッジを大量に並べる
- 意味の薄い海外人物写真を使う
- AI感の強い不自然な人物を使う
- 背景動画や3D演出で読み込みを遅くする
- H1を極端に大きくして説明を画面外へ押し出す
- 要素を詰め込みすぎて焦点がなくなる

# PART 4. LP全体の視線誘導とスクロール設計

## 4-1. 説得の流れを可視化する

デザインは、構成シートで決めた説得順序を崩さない。

代表的な流れ：

1. 関心を得る
2. 悩みを自分事化する
3. 解決策を理解する
4. ベネフィットを想像する
5. 根拠を確認する
6. 比較・不安を解消する
7. 条件を理解する
8. 行動する

この順番は案件ごとに変更できるが、訪問者の疑問を飛ばしたままCTAへ急がせない。

## 4-2. スクロールの緩急

- 重要な結論の前後は余白を広くする
- 比較・仕様・FAQなど情報量の多い部分は密度を適切に上げる
- 感情を動かす部分と、事実を確認する部分の見せ方を変える
- 長文が続く場合は見出し、図、写真、数値、引用で視覚的な区切りを作る
- 背景色の切替は意味のある章の変化に使う

## 4-3. セクション余白

| 区切り | PC | スマートフォン |
|---|---:|---:|
| 小 | 64〜80px | 40〜48px |
| 標準 | 96〜120px | 64〜80px |
| 強 | 140〜180px | 88〜112px |

ページ全体で3段階程度に限定する。長いLPでは、スマートフォンの余白が広すぎて間延びしないよう調整する。

## 4-4. コンテンツ幅

- 標準コンテナ：1100〜1200px
- 情報量が多い比較・表：1200〜1320px
- 本文中心：720〜900px
- PC左右余白：最低24px、標準32〜64px
- スマートフォン左右余白：16〜24px

本文を画面幅いっぱいに広げない。

## 4-5. 要素間の余白

原則として以下のスケールから選ぶ。

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128px`

無秩序な数値を増やさない。

## 4-6. 長いLPでの現在地

必要に応じて、次の手段を使う。

- セクションラベル
- 番号
- ステップ表示
- 背景色の切替
- 要約文
- 固定CTA
- アコーディオン

長いグローバルナビを追加して外部ページへの離脱を増やさない。

# PART 5. 配色

## 5-1. 色の役割

- Primary：ブランド・世界観の中心色
- Secondary：補助色
- Accent／CTA：主要行動の強調色
- Background：基本背景
- Surface：カード・パネル背景
- Text Primary：主要文字
- Text Secondary：補助文字
- Border：枠線
- Success／Warning／Error：状態表示

## 5-2. 色数

- ブランドカラー：1〜2色
- CTAカラー：原則1色
- 無彩色：白・黒・グレー
- 状態表示色：必要な場合のみ

配色比率の初期目安は、ベース70％、メイン20％、アクセント10％とする。案件により調整できる。

## 5-3. CTAカラー

CTAカラーはクリック可能な主要行動に限定する。見出し、マーカー、装飾、アイコンへ広く使い回さない。

## 5-4. コントラスト

- 通常文字は原則4.5:1以上
- 大きな文字は原則3:1以上
- 色だけで状態や選択を伝えない
- 薄いグレーの小文字を多用しない

## 5-5. 配色の禁止事項

- 紫・青の派手なグラデーションを理由なく使う
- ネオンカラーを多用する
- セクションごとに別のアクセント色を使う
- CTAカラーを装飾へ流用する
- ブランドと無関係なSaaS風配色を使う
- 淡い背景に淡い文字を置く

---

# PART 6. タイポグラフィ

## 6-1. フォント数

原則2種類以内とする。

- 日本語本文：1種類
- 英字・見出しアクセント：必要な場合のみ1種類

## 6-2. 基本サイズ

| 要素 | PC | スマートフォン |
|---|---:|---:|
| H1 | 48〜72px | 32〜44px |
| H2 | 36〜48px | 28〜36px |
| H3 | 24〜32px | 21〜26px |
| 本文 | 16〜18px | 15〜17px |
| 補足 | 13〜15px | 12〜14px |
| ボタン | 15〜18px | 15〜17px |

固定値だけでなく、必要に応じて`clamp()`を使用する。

## 6-3. 行間と1行の長さ

- 本文の行間：1.6〜2.0
- H1：1.1〜1.3
- H2：1.2〜1.4
- H3：1.3〜1.5
- 日本語本文：1行25〜40文字程度

## 6-4. 改行

- 読点や助詞の直後など、不自然な位置で改行しない
- PC専用の改行がスマートフォンで不自然にならないよう調整する
- キャッチコピーは意味のまとまりで改行する
- 1文字だけ次行へ残る状態を避ける

## 6-5. 強調

使用できる主な手段：

- 太字
- サイズ差
- ブランドカラー
- マーカー背景
- 余白
- 配置

赤字、下線、全文太字、色の使いすぎ、過剰な文字影を避ける。

## 6-6. 意味の薄い英語

英語のセクションラベルは、世界観の補助としてのみ使用する。日本語見出しより目立たせず、英語だけで内容を伝えない。

# PART 7. 写真・画像・図解

## 7-1. 画像の役割

画像は次のいずれかの役割を持たせる。

- 商品の形・品質を見せる
- 利用場面を見せる
- 利用後の状態を想像させる
- 人・会社の信頼を高める
- 実績・変化を証明する
- 仕組みを分かりやすくする
- 感情を動かす

役割を説明できない画像は削除する。

## 7-2. 写真ディレクション

次を案件内で統一する。

- 明るさ
- 色温度
- 彩度
- コントラスト
- 光の方向
- 人物の雰囲気
- 背景
- トリミング
- 被写体との距離

## 7-3. 商品・サービス別の優先素材

| 商材 | 優先する素材 |
|---|---|
| 有形商品 | 商品単体、使用場面、サイズ、質感、同梱物 |
| 無形サービス | 担当者、提供場面、成果、プロセス、画面・成果物 |
| 店舗・予約 | 店舗、スタッフ、施術・接客、設備、アクセス |
| BtoB | 導入現場、製品・システム、数値、工程、支援体制 |
| 高額・相談型 | 担当者、実績、事例、専門性、保証・サポート |

## 7-4. 画像比率

同じ種類の画像は比率を統一する。

`16:9 / 4:3 / 3:2 / 1:1 / 4:5`

## 7-5. 図解

図解は、文章だけでは理解しにくい関係を示す場合に使用する。

- 手順
- 比較
- 仕組み
- 導入前後
- 費用対効果
- 選び方
- 数値の関係

単純な一文を装飾目的で図解しない。

## 7-6. AI生成画像

- 人体、指、文字、ロゴ、商品形状の破綻を確認する
- 実在商品や実績をAI画像で代用しない
- 実在しない人物を顧客・社員・専門家として見せない
- AI生成であることが問題になる用途では使用しない
- ブランドや商材に合う色調へ統一する

# PART 8. CTAと行動導線

## 8-1. コンバージョン

LPの主要コンバージョンは原則1つに絞る。

補助CTAを設ける場合も、主要CTAより弱く表示し、目的を競合させない。

## 8-2. CTAの階層

| 種類 | 用途 | 表現 |
|---|---|---|
| Primary | 最重要行動 | CTA色、塗りつぶし、最も高い視認性 |
| Secondary | 補助行動 | 枠線、薄い背景 |
| Text Link | 軽い補足導線 | テキスト＋矢印等 |

## 8-3. CTAの配置

配置候補：

- ファーストビュー
- ベネフィット理解後
- 実績・事例の確認後
- 料金・オファーの確認後
- FAQ後
- ページ最下部
- スマートフォン固定CTA

全セクション後に機械的に置かない。訪問者が「行動してもよい」と感じる節目へ配置する。

## 8-4. CTA直前の情報

CTA直前には、段階に応じて次の情報を置く。

- 得られる結果
- 費用・条件
- 実績・口コミ
- 保証
- 対応範囲
- 所要時間
- 申込み後の流れ
- 不安解消

## 8-5. ボタン

- タップ領域：最低44px
- 推奨高さ：48〜56px
- 左右padding：20〜32px
- 文字サイズ：15〜18px
- 文言は具体的な行動で統一する

例：

- 無料相談を予約する
- 資料を無料で受け取る
- 見積もりを依頼する
- 空き状況を確認する
- 商品を購入する

「詳しくはこちら」だけに頼らない。

## 8-6. 固定CTA

スマートフォンの固定CTAは、次の場合に検討する。

- LPが長い
- 電話・予約・問い合わせが主目的
- いつでも行動できる利便性が重要

画面を圧迫しない高さとし、本文やCookie表示と重ならないようにする。常時表示が不快な場合は、一定スクロール後に表示する。

# PART 9. 信頼・実績・比較・オファー

## 9-1. 信頼材料

- 導入件数
- 顧客数
- 継続率
- 創業年数
- 資格・認証
- 受賞歴
- 取引先ロゴ
- 顧客の声
- 導入事例
- 担当者・専門家
- 所在地
- 料金
- 提供の流れ
- 保証
- サポート

## 9-2. 実績の見せ方

- 数字は大きく、単位・期間・対象を明示する
- 出典や算定条件を注記する
- ロゴは掲載許可を確認する
- 顧客の声は属性や利用条件を可能な範囲で示す
- 結果に個人差がある場合は適切に注記する

## 9-3. 比較

- 比較軸を先に定義する
- 自社に都合のよい項目だけを選ばない
- 他社を根拠なく否定しない
- 最も重要な差を視覚的に強調する
- 表がスマートフォンで読める形へ再設計する

## 9-4. 料金・オファー

料金ブロックでは、次を迷わず理解できるようにする。

- 何が含まれるか
- 価格
- 税込・税別
- 追加料金
- 契約・解約条件
- 送料・対応地域
- 特典
- 期限・数量条件
- 保証
- 申込み方法

価格だけを極端に大きくし、重要条件を読めない小ささにしない。

## 9-5. 禁止事項

- 根拠のないNo.1
- 架空の数字・口コミ・ロゴ
- 通常価格の実績がない二重価格
- 実態のない残り時間・残数
- 重要条件を極端に小さく表示する
- 効果を保証できない商材で断定表現を使う

---

# PART 10. カード・角丸・影・アイコン

## 10-1. カード

カードは、並列情報をグループ化する場合に使用する。

適する例：

- 特徴
- プラン
- 事例
- ステップ
- FAQ一覧

文章の各段落をすべてカード化しない。

## 10-2. 角丸

| 印象 | 目安 |
|---|---:|
| 信頼・堅実 | 4〜8px |
| 現代的・親しみ | 8〜16px |
| 柔らかい・カジュアル | 16〜24px |

案件内で1〜2段階に限定する。

## 10-3. 影

影は階層や浮遊を示す必要がある場合だけ使う。

- 薄く
- 広く
- 目立たせすぎない
- 枠線で十分なら使わない

## 10-4. アイコン

次を統一する。

- 線画／塗り
- 線の太さ
- サイズ
- 色
- 角の形
- 視覚的な重さ

複数ライブラリを混在させない。重要な意味は文字ラベルも表示する。

---

# PART 11. フォーム

## 11-1. 入力項目

コンバージョン段階に必要な項目だけに絞る。営業上「あれば便利」な項目を初回フォームへ追加しすぎない。

## 11-2. 表示

- プレースホルダーだけで項目名を表現しない
- 必須・任意を明示する
- 入力例を示す
- 選択肢が長い場合は適切に分割する
- スマートフォンの入力キーボードを項目に合わせる

## 11-3. エラー

どの項目を、どう直せばよいか具体的に示す。入力済みの他項目を消さない。

## 11-4. 送信前後

送信前：

- 個人情報の扱い
- 送信後の対応
- 返信目安
- 費用発生の有無

送信後：

- 完了メッセージ
- 自動返信の有無
- 返信時期
- 次の行動
- 連絡先

## 11-5. 離脱対策

- 項目を減らす
- 複数ステップの場合は進捗を示す
- 入力途中で不安になる条件をフォーム前に説明する
- CTA文言とフォームの内容を一致させる
- 入力後に予想外の必須項目を追加しない

---

# PART 12. スマートフォン

## 12-1. モバイルファースト

PC版を縮小するのではなく、スマートフォンで情報の優先順位と順番を再設計する。

## 12-2. 基本ルール

- PCの2〜3カラムは原則1カラムへ変更する
- 必要に応じて画像と文章の順番を入れ替える
- 横スクロールを発生させない
- 比較表はカード化、横スクロール、要点比較等から適切な方式を選ぶ
- 固定ヘッダー・固定CTAで画面を圧迫しない
- セクション余白をPCより適切に縮める
- ボタンを押しやすくする
- 電話番号・フォーム入力を端末に最適化する

## 12-3. スマートフォン確認

- [ ] ファーストビューだけで対象・価値・CTAが分かる
- [ ] 見出しが大きすぎない
- [ ] 1行が長すぎない
- [ ] 不自然な改行がない
- [ ] 横スクロールがない
- [ ] ボタンが押しやすい
- [ ] 画像の重要部分が切れていない
- [ ] 固定要素が本文を隠さない
- [ ] 情報の順番が自然
- [ ] 表・料金・比較が読める
- [ ] フォームが入力しやすい
- [ ] CTAが見つけやすい
- [ ] セクション間が間延びしていない

# PART 13. アニメーション

## 13-1. 目的

アニメーションは次の補助に限定する。

- 情報の出現を自然に伝える
- 状態変化を示す
- 操作に反応する
- 数値や手順の理解を助ける

## 13-2. 基準

- 標準時間：150〜500ms
- 軽いフェード
- 小さな移動
- ホバー・フォーカス
- アコーディオン
- カウントアップ
- 必要最小限のパララックス

## 13-3. 禁止事項

- 全要素を順番に表示する
- 読む前に要素を隠す
- 大きすぎる移動
- 意味のない3D回転
- スクロールを乗っ取る
- 過剰なカーソル追従
- 長すぎる演出
- アニメーションのためだけに重いライブラリを導入する

`prefers-reduced-motion`へ対応する。

---

# PART 14. アクセシビリティ・SEO・表示速度

## 14-1. アクセシビリティ

- 文字と背景のコントラストを確保する
- 小さすぎる文字を避ける
- キーボード操作を可能にする
- フォーカス状態を表示する
- 画像に適切なaltを付ける
- 見出し階層を正しく使う
- ボタンとリンクを使い分ける
- 色だけで状態を伝えない
- フォームにラベルを付ける
- 動きを減らす設定へ対応する

## 14-2. HTML構造

- H1は原則1ページ1つ
- H2は主要セクション
- H3はH2の下位項目
- `header / nav / main / section / article / aside / footer`を意味に応じて使う
- 見た目のために見出し階層を変更しない

## 14-3. 基本設定

- title
- meta description
- OGP
- canonical
- favicon
- robots
- sitemap
- alt
- 構造化データ
- コンバージョン計測

## 14-4. 表示速度

- WebPまたはAVIFを優先する
- 画像を表示サイズに合わせて圧縮する
- width・heightを指定する
- ファーストビュー画像の読込み優先度を調整する
- 画面外画像を遅延読込みする
- 不要なJavaScriptを減らす
- 不要なフォントウェイトを読込まない
- 大型ライブラリを無計画に導入しない
- CSSを重複させない

---

# PART 15. LPで禁止する表現

## 15-1. AIが作りがちな見た目

- 紫・青の派手なグラデーション
- 全要素のカード化
- 大きすぎる角丸
- 強すぎるドロップシャドウ
- 意味のない光彩・ネオン
- 絵文字のアイコン代用
- 同じカードの大量羅列
- 中央揃えだらけの文章
- 全セクションが同じ構図
- 意味の薄い英語見出し
- 小さい文字による高級感の演出
- 無関係な海外人物写真
- ブランドと無関係な3Dオブジェクト
- 背景装飾の多用
- SaaS風テンプレートの無条件流用
- 内容より見た目を優先すること

## 15-2. LP固有の禁止事項

- 複数の商品・コンバージョンを同じ強さで見せる
- 外部リンクやメニューを増やしすぎる
- 訴求設計と異なる順番で見た目を作る
- 長文を分解せず並べる
- CTA文言・色・形を途中で変更する
- すべてのセクションにCTAを置く
- 不安解消前に申込みだけを繰り返す
- 料金や重要条件を分かりにくくする
- 実績・数値・口コミを捏造する
- 偽の緊急性や希少性を作る

# PART 16. デザイン品質の評価

## 16-1. 採点基準

各項目を10点満点で評価する。

| # | 評価項目 | 確認内容 | 点数 |
|---:|---|---|---:|
| 1 | 訴求の明確さ | 誰向け・何・結果が分かる | /10 |
| 2 | 情報の優先順位 | 重要度が見た目で分かる | /10 |
| 3 | 説得の流れ | 疑問・不安に自然な順番で答える | /10 |
| 4 | 視線誘導 | 見出し・画像・CTAへ自然に進む | /10 |
| 5 | 配色・コントラスト | 世界観と読みやすさを両立する | /10 |
| 6 | タイポグラフィ | サイズ・行間・改行が適切 | /10 |
| 7 | 余白・レイアウト | 規則性と緩急がある | /10 |
| 8 | 写真・図解 | 役割・品質・統一感がある | /10 |
| 9 | 信頼・CTA・フォーム | 根拠が伝わり行動しやすい | /10 |
| 10 | スマホ・技術品質 | 操作性・速度・アクセシビリティ | /10 |
|  | 合計 |  | **/100** |

## 16-2. 合格基準

- 90〜100点：公開・納品候補
- 80〜89点：軽微な修正後に公開可能
- 70〜79点：主要部分の改善が必要
- 60〜69点：デザイン方針または構成を再検討
- 59点以下：要件・訴求設計から再確認

原則として、合計80点以上かつ各項目6点以上を公開候補とする。

## 16-3. 採点の注意

- AIの自己採点だけで合格としない
- 実機・画面キャプチャで確認する
- 点数だけでなく、根拠と修正案を記録する
- 最終判断は人が行う
